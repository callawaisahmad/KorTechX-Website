Under the hood

The technical detail

A precis of how we actually work — the standards, stack and checks behind plugin development.

WordPress plugins and standards

We write to the platform, not against it. Hooks (actions and filters) instead of core file hacks, WordPress coding standards checked by PHPCS, and strict security hygiene: nonce verification, capability checks, input sanitisation, output escaping and prepared statements throughout.

  • Update-safe patterns: prefixed namespaces, DB migrations on activation, no data loss on upgrade
  • Performance-conscious: cached transients, minimal queries, proper enqueue strategy so assets load only where needed
  • Compatible across PHP 7.4–8.x and tested on a version matrix before every release

Shopify apps and webhooks

We build public and custom Shopify apps the right way: App CLI scaffold, backend app structure, and the GraphQL Admin API for product, order and customer operations. App installs use the OAuth flow, and incoming webhooks verify HMAC signatures so you can trust the data.

  • App Bridge for embedded surfaces, scoped access tokens requested and handled, uninstall-cleanup routines
  • Typical no‑code connections: product sync, order notifications, inventory and tag automation
  • App Store submission requirements met in the first submission — scopes, privacy URLs and schema included

Browser extensions (Manifest V3)

For Chrome and Firefox we build to Manifest V3: service workers, messages and permissions declared minimally, and a CSP that keeps reviewers happy. The extension ships with storage scoped to what it actually needs.

  • Background logic in a service worker with offline-safe storage patterns
  • Store-listing assets and QA documentation prepared for the review queue

FAQ

Common questions

Can you fix or extend an existing plugin?+

Absolutely — we audit, patch and extend third-party or legacy plugins as well as build from scratch.

Do you publish to marketplaces?+

Yes, we can prepare and submit apps/extensions to the WordPress, Shopify and browser stores.

Will the plugin break when WordPress, Shopify or Chrome updates?+

We build to the platform's public, supported surfaces and test against a version matrix before every release. Deprecations are reviewed each cycle and you're told what's affected in plain language before an upgrade.

How do you secure a custom plugin?+

Nonce verification, capability checks, input sanitisation and output escaping, prepared SQL statements, no secrets in logs, and POST-only mutations where sensible. What ships is hardened against the OWASP Top 10 for plugins.

Can you audit an existing third-party plugin we run?+

Yes — we review code for security, performance and update-safety, write up findings with a risk level, and either patch what's broken or document the exposure so you can decide.

What does post-launch support include?+

An optional retainer: compatibility fixes, small enhancements, security monitoring and marketplace-compliance maintenance (store requirements change) so your extension stays listed and current.

Do you handle marketplace submission for us?+

Yes — we prepare the app/extension, listing assets, privacy URLs and scopes, then manage the review feedback rounds until it's live in the WordPress, Shopify or browser store.
