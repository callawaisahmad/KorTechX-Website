The technical detail

A precis of how we actually work — the standards, stack and checks behind web development.

How we engineer the build

Every KorTechX site is written, not assembled. That means a semantic HTML5 document tree with ARIA landmarks, a CSS custom-property design system instead of duplicated styles, and JavaScript used sparingly with progressive enhancement and a no-JS fallback. We enforce a performance budget at build time, not after the site is slow.

  • Core Web Vitals targets (mobile, 75th percentile): LCP under 2.5s, INP under 200ms, CLS under 0.1 — gated by Lighthouse CI on every pull request
  • Asset pipeline: WebP/AVIF images with responsive srcset, font subsetting, critical CSS, fetchpriority and preload for above-the-fold resources
  • Deliverables by stack: statically generated or server-rendered Next.js, WordPress served with server-level cache plus object cache and CDN, or Shopify/WooCommerce themes engineered not to crash your Core Web Vitals score

SEO, structured data and measurement — baked in

There is no 'add SEO later'. We ship canonical and clean URL rules (Apache/nginx rewrites), an XML sitemap, and JSON-LD schema per page type — Organization, Service, LocalBusiness, FAQPage, BlogPosting — from the first template. Analytics lands consent-first (GA4) and we verify the property in Search Console during launch.

  • Schema markup validated against schema.org and Rich Results tests before go-live
  • Open Graph and Twitter card tags on every page with a real og-image asset
  • Log: LCP/INP/CLS field data reviewed monthly so rankings aren't quietly hurt by a regression

Accessibility and quality assurance

We score against more than Google. Keyboard navigation, focus rings, contrast ratios and screen-reader semantics are checked against WCAG 2.2 AA as part of QA, and we test across a device matrix (iOS, Android, desktop) plus the latest two browser versions.

  • Automated accessibility checks in CI plus a manual pass on key templates
  • Cross-browser/device screenshot comparison on every release
  • A packaged handover: repo, documented code, CMS training and credentials vault

FAQ

Common questions

Do you build on WordPress or custom code?+

Both. We recommend the right tool for your goals — custom code for performance-critical or bespoke needs, WordPress/Shopify when content-editing flexibility matters most.

Will I be able to edit the site myself?+

Yes. We hand over a documented CMS and a short training session so your team can update content confidently.

How long does a website take?+

A typical marketing site is 2–4 weeks from kickoff to launch, depending on scope and content readiness.

What Core Web Vitals targets do you build to?+

Mobile 75th-percentile budgets: LCP under 2.5s, INP under 200ms, CLS under 0.1. We gate them with Lighthouse CI on every build and review real field data monthly so rankings aren't quietly eroded by a speed regression.

Custom code versus page builders — does it matter for SEO?+

Yes. Page builders inject heavy runtime CSS/JS and fragile markup that fight Core Web Vitals and crawl quality. Hand-coded sites give a clean DOM, controlled rendering and exact placement of JSON-LD schema — which is why we write sites rather than assemble them.

How do editors change content without slowing the site down?+

With a properly hardened setup — static or server-rendered pages served from cache, or WordPress with server-level cache, object cache and a CDN. Editors update content, not layout code, so speed stays green.

Do you include structured data and social tags out of the box?+

Yes — JSON-LD per page type (Organization, Service, LocalBusiness, FAQPage, BlogPosting), plus canonical rules, XML sitemap, Open Graph and Twitter cards, all validated against schema.org and Rich Results tests before launch.

What does ongoing maintenance look like?+

An optional monthly care plan: core/plugin updates, backups with tested restore, uptime monitoring, security patches, small content edits and a quarterly Core Web Vitals and SEO health report.
